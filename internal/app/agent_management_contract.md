# Management API

All endpoint paths below are relative to `/api` on the management listener. Stored private keys and bearer credentials are never returned by normal read APIs. Use the dashboard for interactive management, or a cookie jar for automation:

- `GET /setup`, `POST /setup` (`username`, `password`, `secret`): one-time administrator bootstrap.
- `POST /login` (`username`, `password`): returns username and CSRF token and sets the session cookie. `GET /me` returns the current CSRF token. `POST /logout` revokes the session.
- `GET /status`: this replica's loaded version, database refresh health, propagation interval, and access log drop count.
- `GET /sites`, `POST /sites`, `PUT /sites/{id}`, `DELETE /sites/{id}`: site management. Write fields: `name`, `hostnames`, `upstream`, nullable `certificate_id`, `redirect_https`, `preserve_host`, `enabled`. Send all fields on PUT. POST also accepts optional `initial_policy_id` for atomic default-policy assignment; PUT rejects that create-only field when nonzero.
- `GET /certificates`: metadata, validity, and assignments. `POST /certificates`, `PUT /certificates/{id}`: `name`, `chain_pem`, `private_key_pem`. PUT replaces an uploaded certificate only. `DELETE /certificates/{id}` requires no assignments or active jobs.
- `GET /acme/directory?url=staging|production|<encoded HTTPS URL>`: discover CA terms.
- `GET /acme/accounts`, `POST /acme/accounts`: registration fields `directory` (`staging`, `production`, or HTTPS URL), `email`, `accept_terms: true`.
- `POST /acme/certificates`: `name`, `domains`, `account_id`, optional `challenge_type` (`http-01` by default or `dns-01`), and `dns_credential_id` for DNS-01; returns 202 after queuing issuance. Attach it to sites after issuance succeeds.
- `GET/POST /dns/credentials`, `PUT/DELETE /dns/credentials/{id}`: encrypted Cloudflare token management; read APIs return metadata only.
- `POST /certificates/{id}/renew`: queue immediate reissuance of an ACME-managed certificate using its saved account and HTTP-01/DNS credentials, regardless of expiration. Returns 202 `{id:<job_id>,certificate_id,queued:true}`. Uploaded PEM certificates and existing active issuance/retry jobs return 409. Existing material stays active until successful replacement; new key material is generated by the worker. Requires session/CSRF or MCP certificates scope.
- `GET /acme/jobs`, `POST /acme/jobs/{id}/retry`: newest 100 jobs with order history; retry only accepts jobs in `retry` state.
- `GET /audit`, `GET /access-logs`: latest 200 records.
- `GET /access-logs/{id}`: request metadata, recorded policy/custom-rule definitions, matched managed-signature metadata and only unexpired retained evidence. See [request investigation](request-investigation.md).
- Rule lifecycle, JSON schema, traffic settings, evidence and offline replay: see the [rules API](rules.md#management-api).

For mutations, send `Content-Type: application/json`, `X-Requested-With: aegis-waf`, and the current `X-CSRF-Token` (except setup/login, which have no session yet). Errors return JSON with an `error` field. Database failures return 503 without claiming success; invalid input returns 400; conflicts return 409. A connection loss exactly at commit can leave an ambiguous result; refresh state before repeating a create operation.

## Address objects, Geo and agents

- `GET/POST /address-objects`, `PUT/DELETE /address-objects/{id}`: `name`, `description`, one `value` (IP, CIDR or IPv4 dotted subnet), optional `is_local` boolean (new objects default false; omitted on PUT preserves the flag). Groups use `GET/POST /address-groups`, `PUT/DELETE /address-groups/{id}` with `name`, `description`, `object_ids`. Selection fields are `{object_ids:[],group_ids:[]}`. Hosts accept `trusted_addresses`, `flood_exempt_addresses`, `bot_exempt_addresses` inside protection; policy `network_access` accepts `block_addresses`, `allow_addresses` alongside literal CIDRs. Referenced deletion/conflicting edits return 409. See [address semantics](address-objects.md).
- `POST /geolocation/local/detect`: explicitly discover this serving replica’s outbound public IP through a fixed HTTPS ipify endpoint (five-second timeout, bounded response, redirects rejected). Returns `{public_ip,provider:"ipify",source:"replica_egress"}` without saving settings; authenticated session and CSRF required, MCP configuration scope. Returns 503 on detection failure; manual entry remains available.
- `GET/PUT /geolocation/local`: shared display-location reference `{public_ip:"<public IPv4/IPv6>"}`; empty clears it. GET also returns cached `country` and optional `region`. Matching local IP objects assign this approximate location to future logs only; real client IPs and Geo enforcement are unchanged. Request records expose `observed_country`, `location_source` (`local_reference`, `local_unlocated`, or empty for observed/legacy), and `location_reference_ip`.
- `POST /geolocation/sync`: `{detail:"country"|"city",auto_sync:true|false,accept_license:true}` returns 202 queued; `GET /geolocation/status` returns data timestamps, job/error/sync status. Existing `POST /geolocation/update` is the synchronous Country-only compatibility endpoint.
- `GET /dashboard/regions?country=US&minutes=15&site_id=1&region=WA`: counts plus up to 20 recent requests. Site/region optional; minutes 5/15/60; `region=unknown` selects missing regions. Logs include `region_code`, `region_name`, `network_access`.
- `GET/PUT /agent-access`: `{enabled:false|true}`. `GET /agent-keys` returns metadata only. `POST /agent-keys`: `{name,scopes:["read"],allowed_addresses:{object_ids:[],group_ids:[]},expires_in_days:90}` returns 201 with a one-time `api_key`. `DELETE /agent-keys/{id}` revokes. Creation requires nonempty valid source selection. Dashboard APIs require administrator session and CSRF.
- `/mcp` on management uses separate bearer authentication, source checks and tool permissions, not dashboard sessions. See [transport, tools and limits](agent-access.md).

Managed policy signatures also accept `scoped_exclusions:[{rule_ids:[942100],path_prefix:"/search",parameters:["q"],client_cidrs:["192.168.1.0/24"]}]`. TrafficSettings accepts opt-in `security_samples` (default false). Legacy `security_events_disabled` no longer disables metadata stdout; true continues to suppress optional sample export. See [scope semantics and telemetry privacy](security-tuning.md).

Policy specifications and local protection settings accept `bot_challenge:{enabled:false,score_threshold:60,clearance_minutes:30,risk_requests_per_second:25,risk_burst:50}`. Verification requires anti-bot to be enabled; Observe records rather than challenging, Block challenges at the score threshold. Bounds are threshold 1–100, clearance 1–120 minutes, positive rate and burst at least as large as rate. Access-log `bot` contains score, threshold, reasons and decision; answers and proof cookies are never returned. See [self-hosted CAPTCHA and failure behavior](bot-protection.md).

Site `headers` also supports `hsts:{enabled:true,max_age_seconds:31536000,include_subdomains:false}`. HSTS is off when absent/disabled; max age accepts 0–63072000 seconds. It is emitted only for native or trusted-proxy HTTPS and overrides upstream HSTS. Enabled HSTS conflicts with a manual Set/Remove of `Strict-Transport-Security`. It does not change upstream CA trust. See [HTTPS security controls](headers-and-cidrs.md#hsts-and-upstream-certificate-trust).

Managed signatures support `body_limit_action` (`reject`, default, or `process_partial`), `response_mode` (`off`, default, `observe`, or `block`), `response_body_limit_bytes` (default 262144; 4096–1048576), `response_body_limit_action` (`reject`, default, or `process_partial`) and `outbound_threshold` (default 4; 1–100). Policy/signature Observe caps response Block. Request `body_limit_bytes` remains 4096–1048576, default 65536 for custom policies. Access-log `managed_signatures` includes separate `response_mode` and `response_inspection` when enabled, with combined detection rule IDs. See [buffered and streaming inspection behavior](body-inspection.md).

Agent scopes: `read` (always included), `evidence`, `draft`, `enforce`, `configuration`, `certificates`, `agent_admin`. Broad management uses `list_management_operations`, `get_management_contract` and `management_operation` with `{method,path,input,simulation_id?}`. Account/session/bootstrap operations and new MCP-key creation are hard-denied regardless of scopes. Existing-key revocation requires `agent_admin`. Configuration changes can affect routing/trust/protection boundaries.

`GET /agent-access/skill` downloads the authenticated `aegis-waf.zip` portable skill bundle (binary ZIP, not JSON). MCP `get_agent_skill` returns the same files as structured documentation, separately from general management operations. Import behavior depends on the agent client.

Dashboard adds `response_statuses` (up to 100 groups): `site_id`, current `site_name`/`hostnames`, `response_source`, `status`, `requests`. The existing aggregate `statuses` remains compatible. Access records include stored `response_source` (empty for legacy records) and management-read `client_objects` (up to eight names from the most specific currently matching objects). Original peer IPs remain unchanged.

`GET /live-traffic?site_id=1` returns up to 200 recorded requests from the last minute with current proxy-host names, client-object names, country/region, block decision and response source. Site filter is optional. The response includes `events`, `at`, `limit`, `window_seconds` and `refresh_seconds`; the dashboard polls once per second. This is a bounded best-effort tail, not a lossless stream or active TCP connection feed.

The live-traffic response includes `gateway_location:{public_ip,country,region,map_point?}` and optional per-event `map_point:{latitude,longitude}`. Coordinates come from cached City data and must match the recorded country; local-assigned events use their recorded reference IP. The management-only lookups do not add forwarding work or external client Geo queries.

View-only local filtering: `GET /live-traffic?exclude_local=true` excludes recorded `local_reference`/`local_unlocated` entries before the tail limit. `GET /dashboard?map_exclude_local=true` filters only country/origin aggregates; overview totals remain global for the selected application. `GET /dashboard/regions?exclude_local=true` filters regional aggregates and recent entries. Defaults include local traffic; logs and enforcement are unchanged.

## MCP simulation safety gate

MCP protection mutations require `simulate_rule_impact` followed by the exact operation with its `simulation_id`. Receipts are single-use, expire after two minutes and bind the issuing key, candidate and configuration version. Missing or invalid receipts return 428; regular dashboard requests retain session/CSRF authorization. See [simulation inputs, coverage and workflow](agent-access.md#required-simulation-before-live-protection-changes).

## Proxy host streaming profiles

Site writes also accept `traffic_profile` (`web`, default, `api`, or `streaming`) and `stream_window_bytes` (4096–65536, default 8192). API and streaming profiles return JSON gateway denials, omit browser-header mismatch scoring and do not issue/accept browser CAPTCHA clearance. Suspicion above the policy threshold blocks in Block mode; Observe records it. Website retains selective CAPTCHA. Streaming flushes immediately and uses bounded response windows when policy response inspection is enabled. A match can terminate remaining output, not retract previously sent bytes. See [streaming behavior and telemetry](body-inspection.md#sse-and-streaming-api-profiles).

## Shared counter settings

Shared counter configuration: `GET/PUT /rate-state`, `POST /rate-state/test`. Fields are `backend` (memory/redis), `address` (host:port), optional `username`/write-only `password`, `clear_password`, `tls`, `timeout_ms` (20–250, default 100), and current `revision`. Reads return nested `settings`, `has_password`, loaded revision and failure count. Configuration scope covers MCP; PUT requires simulation. See [optional Redis/Dragonfly counters](shared-rate-state.md).

## Metrics

`GET /metrics` on the management listener returns authenticated Prometheus exposition using a dashboard session or source-restricted Read key over HTTPS (MCP enablement is independent). `GET /api/metrics` is a session/MCP-readable alias. Scrape every replica; counters are replica-local and reset on restart. See [observability, labels and histogram semantics](observability.md).

## Alerts and notifications

All routes below use the `/api` prefix and session/CSRF or the matching scoped MCP management operation. `GET /alerts`, `GET /alerts/{id}`, `GET /alert-deliveries`, `GET /alert-rules` and `GET /notification-channels` require Read. Notification/rule writes, test sends and acknowledgement require Configuration. They do not require rule simulation.

- `GET /alerts?after_id=0&unacknowledged=true`: up to 200 alert objects. `after_id` selects ascending cursor order; absent selects newest first. Alert fields: `id,rule_id,at,kind,site_id,title,count,window_start,window_end,acknowledged_at,acknowledged_by`.
- `POST /alerts/{id}/acknowledge` with `{}`: persist reviewed status; idempotent state, audited invocation.
- `GET /alert-deliveries`: latest 200 delivery records with `id,alert_id,channel_id,status,attempts,error,next_attempt`.
- `POST /notification-channels`, `PUT /notification-channels/{id}`: `{name,provider,enabled,revision?,config?:{url,secret,allow_private}}`. Providers: `automation,webhook,slack,discord,gotify,ntfy,apprise`. Creation/provider changes require config; omission on edit retains encrypted settings. PUT requires current revision. Automation secret must be at least 32 bytes. Read fields: `id,name,provider,enabled,revision,has_config`; no URL or secret.
- `DELETE /notification-channels/{id}`: requires removing rule references first. `POST /notification-channels/{id}/test` with `{}` explicitly sends a saved-destination test, even if disabled.
- `POST /alert-rules`, `PUT /alert-rules/{id}`: `{name,enabled,kind,site_id,threshold,window_minutes,cooldown_minutes,channel_ids,revision?}`. Kinds: `blocked_volume,upstream_errors,certificate_expiry,acme_failure`. `site_id:0` means global. Counts 1–1000000, expiry days 1–90, window 1–60 minutes, cooldown 1–10080 minutes. PUT requires current revision. `DELETE /alert-rules/{id}` removes the trigger, preserving prior inbox/history records.

See [setup, provider credentials, HMAC verification, delivery guarantees and MCP workflow](alerts.md).

## Workspace rule catalogues

`POST /api/rule-feeds` accepts `name`, `url` and optional `site_id`. Omit `site_id` or use `0` for a version 3 packaged workspace release (legacy version 2 manifests remain supported); positive IDs retain version 1 application imports. `GET /api/rule-catalog` lists available shared rules with stable `id`, `feed_id`, `entry_id`, `revision`, `digest`, `spec`, `pack`, `cves` and `feed_name`. Use these IDs in policy group `rule_ids`, alongside native rule IDs. `GET /api/rule-feeds/{id}/items` includes full metadata, availability, and pinned-policy/update status. Existing sync/delete endpoints support both scopes; `/import` accepts legacy application sources only.

Policies store frozen specs with optional `feed` provenance. Ordinary saves preserve those snapshots. Policy writes accept `refresh_rule_ids:[id]` to refresh only selected rules, or `refresh_rules:true` for all selected snapshots. Send the complete policy input and its current `revision`. Removed entries/sources retain published copies but cannot supply a refresh. Sync never activates rules; changed catalogue definitions invalidate existing MCP simulations. Simulate the exact policy write, including refresh fields, before executing it. Catalogue reads use the existing MCP read permission. See [format, limits and compatibility](rule-feeds.md).

## Policy-owned community mitigation selection

Policy `spec.community_mitigations` accepts `{ "enabled": true, "mode": "inherit", "rule_ids": [1, 2] }`. These IDs must reference available catalogue rules or existing frozen catalogue copies. Disable with `enabled:false` while retaining IDs to preserve the selection. Enable requires at least one rule; at most 100 policy rules apply. Responses contain `enabled`, `mode` and frozen `rules` with provenance, rather than writable snapshots. Omission on an existing policy preserves its community selection; new custom policies default off. Legacy feed-derived group rules retain their scopes and obey an explicit community selection/switch; native groups remain independent. Community `mode` accepts `inherit` (follow policy), `observe` or `block`; policy Observe/Off caps enforcement. Omitted mode preserves the existing value on update and defaults to `inherit` on creation or historical revisions. Native rules retain their frozen `action`, downgraded to Observe by policy Observe and skipped by policy Off. A Block policy never promotes a native Observe rule.

Use `refresh_rule_ids` to refresh selected mitigation snapshots, or `refresh_rules:true` to refresh all selected library snapshots. All-selection is a UI bulk selection of the current catalogue, not automatic future activation. MCP policy writes still require exact-candidate simulation. The shipped baseline enables all bundled community rules; a one-time upgrade adds the absent field while preserving other settings and assignments. Feed pages manage subscriptions/review only.

### Curated managed sets and sensitivity

`POST /api/signature-sets` retains `{id}` for loading the current bundled set. Alternatively send `{name,source_set_id,selected_rule_ids:[942100]}` to create a compiled, immutable curated artifact from one installed original source. Do not combine `id` and curation fields. At least one unique selectable detection ID is required, at most 4096; setup/scoring/control IDs are not selectable. Nested curated sources are rejected. Creation is idempotent for identical name/source/selection and capped at 64 curated artifacts. It uses administrator session/CSRF or existing MCP `enforce` scope and audits `signature_set.curated`; creation alone changes no policy.

Set summaries include nullable `curation:{source_set_id,source_version,source_digest,selected_rule_ids}`. Inventory entries include `selectable`; curated inventories contain the chosen detections plus retained support entries. Stored `rule_count` retains its source-file ID accounting. Normal APIs omit raw directive files. `GET /api/signature-sets/{id}/updates` returns `{source,available,changed_rule_ids,removed_rule_ids}`; changes conservatively mean selected rules affected by changed detector files, retained helper files or shared data in the current newer bundled source. Reads require authenticated management access or MCP `read`. Review/save creates another artifact and requires an explicit policy update to adopt it.

Sensitivity is frontend-only and adds no writable policy field. Presets (paranoia/inbound/outbound) are Relaxed 1/10/10, Standard 1/5/4, Elevated 2/5/4, Aggressive 3/3/3 and Maximum 4/2/2. Custom values remain supported. Policy mutation simulation requirements and Observe caps are unchanged.

## Verified upstream TLS and diagnostics

Site writes accept `upstream_tls:{server_name:"backend.internal",trusted_certificates_pem:"-----BEGIN CERTIFICATE-----..."}`. The server name overrides TLS SNI/hostname verification only; it does not alter the HTTP Host header. Trusted public CA certificates or explicit server-certificate pins augment normal system trust for this host. Private keys are rejected; verification remains enabled. Omission on PUT preserves stored trust; `{}` explicitly clears it. Trust changes are live-protection mutations and require the usual exact simulation receipt for agents.

`POST /upstreams/test` requires Configuration scope and accepts `{upstream:"https://backend.internal:8443",upstream_tls:{...},host_header:"public.example.com"}`. It makes a bounded GET from the current replica with no application credentials and no redirects, without saving configuration. Result fields: `reachable`, optional HTTP `status`, `stage`, plain-language `message`, `tls_verified`, and `duration_ms`. A reachable HTTP401/403/5xx is different from DNS/TLS/network failure. Maximum four tests concurrently per replica, eight-second request timeout; probes are audited without URL paths/certificate contents. See [upstream connections](upstreams.md).

## Policy API methods, stream windows and connection limits

Policy `spec.managed_signatures` accepts optional `allowed_methods` (up to16 uppercase HTTP method names; omitted/empty uses host-profile defaults) and `stream_window_bytes` (4096–65536, or0/omitted to preserve the legacy host fallback). API/SSE automatic defaults add PUT/PATCH/DELETE to the bundled web GET/HEAD/POST/OPTIONS; CRS911100 must be selected for method enforcement. Explicit lists match exact tokens. Selecting API/SSE never disables request attack signatures.

Policy `spec.connection_limits` optionally accepts `{enabled:true,max_concurrent:100,max_per_client:10,max_duration_seconds:900,idle_timeout_seconds:60}`. Omitted is disabled; maximum concurrent1–10000, client1–application cap, duration1–86400s, idle1–3600s. Scope is application+selectedpolicy+replica, independently of shared rate counters. Block enforces, Observe records, Off disables; full WAF bypass skips. Active counts survive reload; configuration changes affect new requests. Streaming timeouts after headers cut the stream with its original status; before headers timeout504, capacity429. Live connection/time behavior is not reconstructed by offline simulation; inspect its warnings. These policy changes require the normal exact simulation receipt for agents.

The upstream probe can return public `certificate:{pem,sha256,subject,issuer,not_after,can_trust}` metadata. `can_trust` is offered for an unknown issuer only when hostname and validity checks pass; no private key or verification bypass is provided. Import an independently verified CA when possible; pinning the shown server certificate requires updating the pin on rotation.

## Global log retention

`GET /log-settings` returns the shared `retention_hours` (default6, range1–8760) and optimistic `revision`; `last_export_at`, `last_cleanup_at`, `export_error`, `cleanup_error`; pending access/audit export booleans; cumulative `access_deleted`, `audit_deleted`, `evidence_deleted`; combined `log_storage_bytes` including indexes/reusable space; and current-replica `dropped_stdout_logs` / `dropped_database_logs` counters.

`PUT /log-settings` requires `{retention_hours:6,revision:1}` and Configuration scope (or an authenticated administrator with CSRF). Stale revisions return409; invalid ranges return400. A successful transaction updates the configuration version and records `logging.retention.updated` without secrets. There is no synchronous purge. Cleanup applies to access logs, administrative audits and request samples across replicas. Samples may expire sooner under their application capture settings. Existing access/audit records must be exported to stdout before deletion; successful stdout writes do not acknowledge SIEM receipt. Alerts, configuration revision history, Docker rotation and external collector retention are separate. See [logging and delivery behavior](logging.md).
