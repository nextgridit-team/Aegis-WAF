# Management API

All endpoint paths below are relative to `/api` on the management listener. There are no bearer-token or private-key export APIs. Use the dashboard for interactive management, or a cookie jar for automation:

- `GET /setup`, `POST /setup` (`username`, `password`, `secret`): one-time administrator bootstrap.
- `POST /login` (`username`, `password`): returns username and CSRF token and sets the session cookie. `GET /me` returns the current CSRF token. `POST /logout` revokes the session.
- `GET /status`: this replica's loaded version, database refresh health, propagation interval, and access log drop count.
- `GET /sites`, `POST /sites`, `PUT /sites/{id}`, `DELETE /sites/{id}`: site management. Write fields: `name`, `hostnames`, `upstream`, nullable `certificate_id`, `redirect_https`, `preserve_host`, `enabled`. Send all fields on PUT. POST also accepts optional `initial_policy_id` for atomic default-policy assignment; PUT rejects that create-only field when nonzero.
- `GET /certificates`: metadata, validity, and assignments. `POST /certificates`, `PUT /certificates/{id}`: `name`, `chain_pem`, `private_key_pem`. PUT replaces an uploaded certificate only. `DELETE /certificates/{id}` requires no assignments or active jobs.
- `GET /acme/directory?url=staging|production|<encoded HTTPS URL>`: discover CA terms.
- `GET /acme/accounts`, `POST /acme/accounts`: registration fields `directory` (`staging`, `production`, or HTTPS URL), `email`, `accept_terms: true`.
- `POST /acme/certificates`: `name`, `domains`, `account_id`, optional `challenge_type` (`http-01` by default or `dns-01`), and `dns_credential_id` for DNS-01; returns 202 after queuing issuance. Attach it to sites after issuance succeeds.
- `GET/POST /dns/credentials`, `PUT/DELETE /dns/credentials/{id}`: encrypted Cloudflare token management; read APIs return metadata only.
- `POST /certificates/{id}/renew`: queue immediate reissuance of an ACME-managed certificate using its saved account and HTTP-01/DNS credentials, regardless of expiration. Returns 202 `{id:<job_id>,certificate_id,queued:true}`. Uploaded PEM certificates and existing active issuance/retry jobs return 409. Existing material stays active until successful replacement; new key material is generated by the worker. Requires session/CSRF or MCP certificates scope.
- `GET /acme/jobs`, `POST /acme/jobs/{id}/retry`: newest 100 jobs with order history; retry only accepts jobs in `retry` state.
- `GET /audit`, `GET /access-logs`: latest 200 records.
- `GET /access-logs/{id}`: request metadata, recorded policy/custom-rule definitions, matched managed-signature metadata and only unexpired retained evidence. See [request investigation](request-investigation.md).
- Rule lifecycle, JSON schema, traffic settings, evidence and offline replay: see the [rules API](rules.md#management-api).

For mutations, send `Content-Type: application/json`, `X-Requested-With: aegis-waf`, and the current `X-CSRF-Token` (except setup/login, which have no session yet). Errors return JSON with an `error` field. Database failures return 503 without claiming success; invalid input returns 400; conflicts return 409. A connection loss exactly at commit can leave an ambiguous result; refresh state before repeating a create operation.

## Address objects, Geo and agents

- `GET/POST /address-objects`, `PUT/DELETE /address-objects/{id}`: `name`, `description`, one `value` (IP, CIDR or IPv4 dotted subnet), optional `is_local` boolean (new objects default false; omitted on PUT preserves the flag). Groups use `GET/POST /address-groups`, `PUT/DELETE /address-groups/{id}` with `name`, `description`, `object_ids`. Selection fields are `{object_ids:[],group_ids:[]}`. Hosts accept `trusted_addresses`, `flood_exempt_addresses`, `bot_exempt_addresses` inside protection; policy `network_access` accepts `block_addresses`, `allow_addresses` alongside literal CIDRs. Referenced deletion/conflicting edits return 409. See [address semantics](address-objects.md).
- `POST /geolocation/local/detect`: explicitly discover this serving replica’s outbound public IP through a fixed HTTPS ipify endpoint (five-second timeout, bounded response, redirects rejected). Returns `{public_ip,provider:"ipify",source:"replica_egress"}` without saving settings; authenticated session and CSRF required, MCP configuration scope. Returns 503 on detection failure; manual entry remains available.
- `GET/PUT /geolocation/local`: shared display-location reference `{public_ip:"<public IPv4/IPv6>"}`; empty clears it. GET also returns cached `country` and optional `region`. Matching local IP objects assign this approximate location to future logs only; real client IPs and Geo enforcement are unchanged. Request records expose `observed_country`, `location_source` (`local_reference`, `local_unlocated`, or empty for observed/legacy), and `location_reference_ip`.
- `POST /geolocation/sync`: `{detail:"country"|"city",auto_sync:true|false,accept_license:true}` returns 202 queued; `GET /geolocation/status` returns data timestamps, job/error/sync status. Existing `POST /geolocation/update` is the synchronous Country-only compatibility endpoint.
- `GET /dashboard/regions?country=US&minutes=15&site_id=1&region=WA`: counts plus up to 20 recent requests. Site/region optional; minutes 5/15/60; `region=unknown` selects missing regions. Logs include `region_code`, `region_name`, `network_access`.
- `GET/PUT /agent-access`: `{enabled:false|true}`. `GET /agent-keys` returns metadata only. `POST /agent-keys`: `{name,scopes:["read"],allowed_addresses:{object_ids:[],group_ids:[]},expires_in_days:90}` returns 201 with a one-time `api_key`. `DELETE /agent-keys/{id}` revokes. Creation requires nonempty valid source selection. Dashboard APIs require administrator session and CSRF.
- `/mcp` on management uses separate bearer authentication, source checks and tool permissions, not dashboard sessions. See [transport, tools and limits](agent-access.md).

Managed policy signatures also accept `scoped_exclusions:[{rule_ids:[942100],path_prefix:"/search",parameters:["q"],client_cidrs:["192.168.1.0/24"]}]`. TrafficSettings accepts `security_events_disabled` and `security_samples`, both default false. See [scope semantics and telemetry privacy](security-tuning.md).

Policy specifications and local protection settings accept `bot_challenge:{enabled:false,score_threshold:60,clearance_minutes:30,risk_requests_per_second:25,risk_burst:50}`. Verification requires anti-bot to be enabled; Observe records rather than challenging, Block challenges at the score threshold. Bounds are threshold 1–100, clearance 1–120 minutes, positive rate and burst at least as large as rate. Access-log `bot` contains score, threshold, reasons and decision; answers and proof cookies are never returned. See [self-hosted CAPTCHA and failure behavior](bot-protection.md).

Site `headers` also supports `hsts:{enabled:true,max_age_seconds:31536000,include_subdomains:false}`. HSTS is off when absent/disabled; max age accepts 0–63072000 seconds. It is emitted only for native or trusted-proxy HTTPS and overrides upstream HSTS. Enabled HSTS conflicts with a manual Set/Remove of `Strict-Transport-Security`. It does not change upstream CA trust. See [HTTPS security controls](headers-and-cidrs.md#hsts-and-upstream-certificate-trust).

Managed signatures support `body_limit_action` (`reject`, default, or `process_partial`), `response_mode` (`off`, default, `observe`, or `block`), `response_body_limit_bytes` (default 262144; 4096–1048576), `response_body_limit_action` (`reject`, default, or `process_partial`) and `outbound_threshold` (default 4; 1–100). Policy/signature Observe caps response Block. Request `body_limit_bytes` remains 4096–1048576, default 65536 for custom policies. Access-log `managed_signatures` includes separate `response_mode` and `response_inspection` when enabled, with combined detection rule IDs. See [inspection behavior and streaming exemptions](body-inspection.md).

Agent scopes: `read` (always included), `evidence`, `draft`, `enforce`, `configuration`, `certificates`, `agent_admin`. Broad management uses `list_management_operations`, `get_management_contract` and `management_operation` with `{method,path,input}`. Account/session/bootstrap operations and new MCP-key creation are hard-denied regardless of scopes. Existing-key revocation requires `agent_admin`. Configuration changes can affect routing/trust/protection boundaries.

`GET /agent-access/skill` downloads the authenticated `aegis-waf.zip` portable skill bundle (binary ZIP, not JSON). MCP `get_agent_skill` returns the same files as structured documentation, separately from general management operations. Import behavior depends on the agent client.

Dashboard adds `response_statuses` (up to 100 groups): `site_id`, current `site_name`/`hostnames`, `response_source`, `status`, `requests`. The existing aggregate `statuses` remains compatible. Access records include stored `response_source` (empty for legacy records) and management-read `client_objects` (up to eight names from the most specific currently matching objects). Original peer IPs remain unchanged.

`GET /live-traffic?site_id=1` returns up to 200 recorded requests from the last minute with current proxy-host names, client-object names, country/region, block decision and response source. Site filter is optional. The response includes `events`, `at`, `limit`, `window_seconds` and `refresh_seconds`; the dashboard polls once per second. This is a bounded best-effort tail, not a lossless stream or active TCP connection feed.

The live-traffic response includes `gateway_location:{public_ip,country,region,map_point?}` and optional per-event `map_point:{latitude,longitude}`. Coordinates come from cached City data and must match the recorded country; local-assigned events use their recorded reference IP. The management-only lookups do not add forwarding work or external client Geo queries.

View-only local filtering: `GET /live-traffic?exclude_local=true` excludes recorded `local_reference`/`local_unlocated` entries before the tail limit. `GET /dashboard?map_exclude_local=true` filters only country/origin aggregates; overview totals remain global for the selected application. `GET /dashboard/regions?exclude_local=true` filters regional aggregates and recent entries. Defaults include local traffic; logs and enforcement are unchanged.

## MCP simulation safety gate

MCP protection mutations require `simulate_rule_impact` followed by the exact operation with its `simulation_id`. Receipts are single-use, expire after two minutes and bind the issuing key, candidate and configuration version. Missing or invalid receipts return 428; regular dashboard requests retain session/CSRF authorization. See [simulation inputs, coverage and workflow](agent-access.md#required-simulation-before-live-protection-changes).

Site writes also accept `traffic_profile` (`web`, default, or `streaming`) and `stream_window_bytes` (4096–65536, default 8192). Streaming flushes immediately and uses bounded response windows when policy response inspection is enabled. A match can terminate remaining output, not retract previously sent bytes. See [streaming behavior and telemetry](body-inspection.md#sse-and-streaming-api-profiles).

Shared counter configuration: `GET/PUT /rate-state`, `POST /rate-state/test`. Fields are `backend` (memory/redis), `address` (host:port), optional `username`/write-only `password`, `clear_password`, `tls`, `timeout_ms` (20–250, default 100), and current `revision`. Reads return nested `settings`, `has_password`, loaded revision and failure count. Configuration scope covers MCP; PUT requires simulation. See [optional Redis/Dragonfly counters](shared-rate-state.md).
