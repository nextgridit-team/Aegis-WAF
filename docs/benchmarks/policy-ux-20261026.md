# Policy UX benchmark record — 2026-10-26

Before: base commit `307e336`. After: the uncommitted policy UX review working tree. Both ran on Linux/amd64, AMD Ryzen 9 7950X3D, the cached Go 1.26 toolchain, with three warm samples per case. This is a local microbenchmark, not an end-to-end WAF load test or p50/p99 latency measurement.

| Case                                | Before median | After median | Before/after allocations |
| ----------------------------------- | ------------- | ------------ | ------------------------ |
| Native rule evaluation · 100 rules  | 5.896 µs/op   | 5.763 µs/op  | 4 / 4 allocs/op          |
| Native rule evaluation · 1000 rules | 57.935 µs/op  | 57.399 µs/op | 4 / 4 allocs/op          |
| Identity + resolved protection      | 0.208 µs/op   | 0.219 µs/op  | 1 / 1 allocs/op          |
| Local upstream forwarding           | 30.938 µs/op  | 32.174 µs/op | 101 / 101 allocs/op      |

Hot-path allocation counts are unchanged. Timing differences of a few percent in three samples do not establish either a regression or an improvement. These UX and management changes do not modify the native evaluator, client resolver or forwarding implementation. Forwarding includes one actual local HTTP upstream round trip; native rule cases use literal path matches.

## Curated managed-inspection example

This additional comparison uses the same current Coraza source and Standard request settings (Observe, PL1, inbound 5, outbound 4, response inspection off). Each operation constructs and inspects an ordinary `GET /products?q=chair`, with User-Agent and Accept headers. It excludes TLS, network I/O, PostgreSQL logging, bot/flood protection and end-to-end request scheduling. Artifact creation and compilation are outside the timed section.

| Managed set                               | Median        | Median bytes | Median allocations |
| ----------------------------------------- | ------------- | ------------ | ------------------ |
| Full source                               | 323.510 µs/op | 127970 B/op  | 2539               |
| SQL detector 942100 plus retained helpers | 68.863 µs/op  | 45929 B/op   | 817                |

**The protection coverage differs substantially.** One SQL detector deliberately omits other SQL patterns, XSS and other protections. This example demonstrates the cost of evaluating fewer detectors; it is not a recommended baseline, equivalent-security comparison or general proxy speed claim. It does not measure the sensitivity ladder, and no identical-throughput claim is made across paranoia levels.

Raw outputs: [before](policy-ux-20261026-before.txt), [after](policy-ux-20261026-after.txt). Reproduce with:

```sh
go test ./internal/app -run '^$' -bench 'BenchmarkRuleEvaluation/rules_(100|1000)$|BenchmarkResolvedProtection$|BenchmarkForwarding$|BenchmarkCuratedManaged$' -benchmem -count=3
```
