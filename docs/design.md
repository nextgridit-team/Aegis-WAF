# Aegis WAF console design

The console serves administrators bringing applications online. Its primary workflow is certificate first, proxy host second. The signed-in landing page is Dashboard; certificate onboarding and automatic issuance status live beside the certificate inventory. Certificate authorities are a secondary destination. A new ACME request guides the administrator through authority registration, explicit terms acceptance, domains, and DNS/port-80 prerequisites. Successful issuance exposes Connect site with certificate and hostnames already selected.

The visual system supports light and dark themes with restrained evergreen accents. A compact persistent sidebar, readable tables, native dialogs, consistent outlined icons, and quiet status badges support recurring administration. No external fonts or decorative imagery are loaded. On mobile, navigation moves to a horizontal strip and dialogs fit the viewport; data tables retain accessible horizontal scrolling.

All settings persist through the authenticated Go API and PostgreSQL. Issuance state polls every four seconds while the page is visible and no editing dialog is open. Forms preserve input on failure; authority changes invalidate prior terms acceptance. The interface distinguishes queued, issuing, retrying, valid, and expired certificates. Stored secrets are not returned by normal read APIs; newly created agent keys are shown once. A certificate is only described as ready after the backend reports valid material.

Rules and Traffic extend the same sidebar, tables and dialog patterns. Rule editing starts with an application and simple field/operator/value conditions; JSON import/export supports structured proposals. Mode and expiry remain visible beside each rule. Test against evidence evaluates locally; deliberate activation, disabling and rollback are available from rule details. Traffic sampling is configured per application, is disabled by default, and names its field allowlists and retention limits explicitly. Activity shows rule outcomes even when content capture is disabled.

Certificate requests now use one form: domains, email, and Cloudflare API token. Let's Encrypt production and DNS-01 are the defaults. Saved account/contact and credential metadata are reused without exposing tokens. Advanced options contain staging/custom authorities, HTTP-01, and certificate naming. CA registration and credential persistence happen on submit, with inline progress and recovery of confirmed setup after errors. Terms remain explicit. The advanced authority/provider pages remain management tools rather than onboarding prerequisites.

Recent controls follow the same form patterns: per-host Web/SSE profiles, a collapsed **CIDR access and Geo blocking** section in policy editing, selective CAPTCHA settings and a separate System page for local/shared rate state and Prometheus discovery. System and Agent access inline forms are not replaced by general background polling while being edited. Native management remains separate from protected application listeners.
