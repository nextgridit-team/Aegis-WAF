# Review of the AI build sheet

Historical proposal review: Aegis now exposes external-agent MCP access rather than running the review jobs proposed here. Read [Agent access](agent-access.md) for shipped behavior. Operator approval rules belong to the external playbook; Aegis enforces key scopes and simulation receipts, not a mandatory human-approval workflow.

The proposed first increment should be false-positive triage (#3), then rule drafting (#1). Both can use bounded, opt-in evidence and produce reviewed drafts without adding inference to forwarding. Keep provider setup separate from permission to send traffic data. This review does not enable inference or automated enforcement.

Several claims and implementation details need tightening before building:

- **The nanosecond figure is a microbenchmark.** Roughly 186–208 ns measures local protection checks, not the whole data plane. The measured external proxy workload is approximately 1 ms p50 / 4.3 ms p99 with 100 simple rules in the lab. Use [the measured workload and limits](benchmarks.md) rather than describing forwarding as 208 ns.
- **Replay reduces risk; it does not eliminate it.** Samples may be incomplete, poisoned, unrepresentative, redacted or already expired. A candidate passing the same data that generated it is not independent validation. Require schema validation, held-out benign/attack evidence where available, unknown-result reporting, human approval and an Observe rollout before blocking. Treat “no commercial WAF offers this” as an unverified marketing claim and remove it from product claims.
- **Draft approval should create a rule draft or reviewed policy change.** It should not silently activate protection. Pin proposal evidence IDs, application/policy revision, provider/model, prompt version and replay results. Reject stale approvals and use the existing explicit publish/activate/TTL path. Model rationale is an untrusted claim, not evidence.
- **RunWorker is supervision, not job coordination.** Inference jobs still need PostgreSQL-backed ownership/leases, idempotent proposal insertion, expiry, bounded attempts, cancellation, token/cost limits and visible errors so replicas do not duplicate paid calls. Keep model-list discovery distinct from checking actual chat/schema capabilities; local compatible providers support different inference features.
- **The input data has limits.** Access logs contain client IP/method/status/rule matches, but do not record every endpoint path. Paths exist only in optional sampled evidence and may be redacted. A campaign's distinct-endpoint count is therefore approximate or unavailable. Current geolocation supplies country, not ASN or reliable actor identity. Per-application evidence expiry defaults to24 hours and supports at most seven days, but the global database window defaults to six hours and takes precedence when shorter; longer reports need explicitly configured retention or external logs.
- **NAT and proxies matter for responses.** An IP can represent many legitimate users. Scope any response by application and reliable resolved identity, retain the default policy fallback, bound its TTL/count and show why it fired. Define a separate explicit exemption for automatic responses; a flood-only exemption must not accidentally exempt all future enforcement. Expiry must be checked on every request even before the next snapshot refresh. “Two weeks of watching” should be replaced by measured false-positive and coverage criteria.
- **Prompt delimiters are useful but insufficient.** Models get no management credentials, tools or executable actions. Bound context and output, validate only the supported typed grammar, and keep enforcement limits outside model control. Read-only analysis still has disclosure and misleading-advice risks; call it low enforcement risk, not zero risk.
- **Redaction discovery cannot protect data already sent.** Already-redacted samples cannot reveal hidden values. Proposals may identify residual patterns, but only reviewed RE2 patterns should apply to future evidence. Data residency and backup retention remain deployment responsibilities.
- **CRS replay needs a separate contract.** Existing fact replay can validate the custom DSL. Redacted selected facts cannot faithfully reconstruct complete CRS HTTP transactions, transformations or response context. Do not expand raw collection automatically to support replay. Managed CRS exclusions should be validated IDs/settings, not model-generated arbitrary SecLang.

Suggested delivery contract for the first triage slice: one administrator-requested, application-scoped background job; explicit selected lookback and sharing notice; bounded aggregate counts plus redacted samples; a structured report with uncertainty and cited sample IDs; no automatic policy edits. Add proposals and independent replay checks next. Automated IP responses remain a later, separately controlled enforcement feature.
