# Current limitations

Updated on 2026-10-26, including curated managed sets, sensitivity presets, the merged KEV corpus and packaged feeds. Several earlier gaps are now implemented: CRS request/response inspection, selective CAPTCHA, shared rate counters, atomic reloads, MCP simulation, Prometheus metrics, alerts and individually versioned rule feeds. [Completed improvements and verification](limitations-review.md).

This page describes the remaining boundaries. An optional feature needs configuration before it provides its protection.

## Inspection and detection

- **Inspection is bounded.** New custom policies default to 64 KiB of request inspection; the included baseline uses 1 MiB. Request and optional response limits range from 4 KiB to 1 MiB. Reject or inspect-prefix behavior is configurable; a forwarded tail is uninspected, and truncated structured bodies can still fail parsing. Response inspection is opt-in. Website/API profiles buffer eligible text; SSE profiles inspect overlapping windows after delivery and cannot retract sent bytes. WebSocket frames, binary gRPC and unsupported content types are not body-inspected. At most eight distinct active managed configurations are supported per replica. [Body controls](body-inspection.md).
- **Custom rules have defined semantics.** Missing, redacted, truncated or unsupported facts can be unknown and do not themselves block. Regex uses Go/RE2; paths are not repeatedly decoded, case-folded or normalized like every upstream framework. Native rules use deterministic matching; CRS has separate anomaly scoring. [Rule format and limits](rules.md).
- **Bot identity is not proven by CAPTCHA.** Selective self-hosted image/audio verification and expiring clearance are available. Header signals remain spoofable, and capable bots or solver services can pass challenges. Verified crawler identity and adaptive behavioral learning are not implemented. Network-layer DDoS protection still requires infrastructure outside Aegis. [Bot controls](bot-protection.md).
- **Community guards are partial mitigations.** Individual rules can be selected for policies, but request-pattern guards cover only documented mechanisms, and endpoint-containment guards can disable legitimate operations. PHP multipart and Node.js Brotli guards also reject legitimate uses. They do not detect every exploit path or replace runtime updates. Feed sync preserves pinned policy copies until explicitly refreshed. Package checksums are not independent publisher signatures; only public unauthenticated HTTPS sources are supported. Changed releases download a complete bounded package; signed releases and delta updates remain future work. [Catalogue coverage and compatibility](rule-feeds.md).

- **Curated sets trade coverage for selection.** One installed original CRS source per artifact; arbitrary remote SecLang imports, nested sources and multi-set composition are unsupported. At most 64 curated artifacts and eight active managed configurations per replica are supported. Source files remain stored; removal overlays reduce evaluated detectors rather than the stored corpus. Upstream review is conservative at file/shared-helper level, not a semantic per-rule diff. Sparse sets may not reach full-bundle thresholds, and sensitivity presets are not a latency control or a guarantee against false positives. [Managed-set bounds](managed-signatures.md#sensitivity-and-curated-sets).

## Operations and data

- **Shared budgets are optional.** Local counters remain per replica. Configure Redis/Dragonfly to share flood and bot-frequency budgets; this adds network latency. Enforcing controls return 503 if the shared backend cannot be evaluated. Backend reset/eviction can reset budgets; Redis Cluster/Sentinel discovery and durable counter recovery are not implemented. [Shared state](shared-rate-state.md).
- **Some operations still require PostgreSQL during an outage.** Running replicas keep loaded routes, certificates and policies. Sign-in, administrative changes, metrics authentication, new CAPTCHA verification and HTTP-01 lookup require the database. Cached accepted clearances continue only within their expiry. Default cold starts remain unready; an explicitly configured sealed snapshot permits bounded-staleness recovery. Certificates must still be valid. [Outage behavior](deployment.md#health-and-database-outages) · [Sealed recovery](snapshot-cache.md).
- **Access logging prioritizes forwarding over durability.** Its asynchronous queue can lose records during saturation, outages or crashes. Administrative mutations use transactional audits; those writes fail when their audit cannot commit. Automatic access-log/audit retention is not implemented. Evidence expires automatically, and alert history has separate bounded cleanup; neither cleans access/audit tables. [Logging](logging.md) · [Evidence privacy](evidence-privacy.md).
- **Encryption is applied to secrets, not every database value.** Private keys and saved credentials use AES-256-GCM with an external key. Public certificate chains, configuration and logs are outside that application encryption layer. Online key rotation is not implemented. Back up PostgreSQL and the external key together; deployment storage encryption remains the operator's responsibility. [Encryption at rest](encryption-at-rest.md).

## Administration and automation

- **Administrator MFA, password recovery and granular roles are not implemented.** MCP keys have permission scopes, expiry and source restrictions, but their resource authority spans the workspace rather than selected applications. [Agent permissions](agent-access.md).
- **Agent reasoning runs outside Aegis.** MCP exposes management, investigation and enforced impact simulation; it does not run inference. Receipts bind an exact change to its key/configuration version, but incomplete evidence or unrepresentative tests cannot prove safety or traffic legitimacy. OAuth discovery/dynamic registration are unsupported. An API/SSE proxy profile also does not implement upstream API-key brokerage. [Agent setup](agent-access.md) · [Endpoint profiles](body-inspection.md#sse-and-streaming-api-profiles).
- **Alerts need a configured destination to wake an agent.** Notification delivery is asynchronous, retried and at least once; receivers must deduplicate. The stateless MCP endpoint does not push unsolicited wake-up messages. Configure a webhook receiver/orchestrator or polling agent. [Alerts and delivery guarantees](alerts.md).

Published benchmarks cover specific small workloads, not production capacity, detection completeness or security parity with another WAF. [Measurements and comparison limits](proxy-comparison.md).
